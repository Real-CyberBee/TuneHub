# 02 · 律制、音阶与世界音乐数据

> 调研范围：律制/temperament 软件与数据格式、8–10 个律制家族、拉格/木卡姆/甘美兰的行为结构、可用的机器可读数据源。
> 本文最重要的产出是 **§1 的三层抽象** —— 它决定了整个项目能否真正容纳世界音乐。

---

## 1. 核心洞察：必须拆成三层

把用户列出的 10 类体系并列，会做出错误的抽象。它们实际分属**三个正交层**：

```
律制层 Tuning     频率如何生成？        （等分 / 比例 / 实测频率）
    ↓
音阶层 Scale      取哪些音级？          （五声、七声、12 音子集、24 音子集）
    ↓
框架层 Framework  这些音级怎么用？       （上行下行、重点音、惯用乐句、即兴规则）
```

### 为什么必须拆

| 反例 | 如果只做"音阶"会怎样 |
|---|---|
| **拉格 (Raga)** | 拉格不只是音阶。它有 `aroha`/`avaroha`（上行/下行音序，且两者常不同）、`vadi`/`samvadi`（主次重点音）、`pakad`（特征乐句）。只给音阶 = 永远生成的只是"听起来像印度音阶的随机音" |
| **木卡姆 (Maqam)** | 有 `jins`/`ajnas`（三音/四音细胞）、`seyir`（旋律行进方向与性格）、`taqsim`（即兴前奏规则）。音高还涉及中立三度（约 350 cents 而非 400 或 300） |
| **甘美兰 (Gamelan)** | 斯连德罗/佩洛格不是 12-TET 上的音阶。**每一套合奏的调音都不同**，且是实测频率。用"音阶"承载就必然错 |

> **产品含义**：UI 上必须让用户看到"律制 → 音阶 → 框架"三步，而不是一个扁平的音阶下拉框。这既是技术正确性，也是**教育价值**——用户会理解"音阶不等于音乐体系"。

## 2. 数据格式与工具

### 2.1 Scala 格式（事实标准）

- **`.scl`**：音阶定义文件，每行一个音程（cents 或比例），支持注释
- **`.kbm`**：键盘映射文件，定义如何把音阶映射到 MIDI 键位（含参考音、八度重复、未映射键的处理）

规范由 Manuel Op de Coul 维护于 Huygens-Fokker 基金会网站。这是**跨软件交换律制的通用格式**——支持它的工具包括 Scala、Surge XT、Wilsonic、Scale Workshop 等。

**建议**：TuneHub 以 `.scl`/`.kbm` 作为**导入/导出格式**，内部用更丰富的数据结构。

### 2.2 关键软件与库

| 工具 | 类型 | 许可 | 用途 |
|---|---|---|---|
| **sonic-weave** | npm 包 / DSL | **MIT**（已核实 v0.14.1） | 律制计算内核。支持 `tet(n)`、比例算术、音 comma 消解、FJS 记谱 |
| **Scale Workshop 3** | 浏览器工具 | 见 04 | 交互设计参考；sonic-weave 是它的语言内核 |
| **Scala** | 桌面软件 | 免费（非开源） | 音阶库与格式的事实标准 |
| **Wilsonic** | iOS/桌面 | 见 04 | Erv Wilson 的 CPS/组合积和音阶理论，提供大量非常规音阶 |
| **Surge XT** | 合成器 | GPL | 其 tuning 实现可参考 `.scl` 支持方式 |
| **MTS-ESP (Oddsound)** | 插件 | 专有 | 现代微调插件协议 |
| **Apotome & Leimma** | 浏览器工具 | 见 04 | Khyam Allami / Counterpoint 出品，**阿拉伯与中立音体系**的交互范本 |
| **Leimma** | 浏览器 | 同上 | 专注于音阶的听辨与探索 |

**MTS (MIDI Tuning Standard)** 与 **MPE**：若将来要驱动外部硬件合成器，需支持这两个协议才能传递非 12-TET 音高。MIDI 2.0 的 Per-Note Pitch Bend 允许每个音符独立弯音，是微分音的未来方向。

### 2.3 sonic-weave 具体能力（已核实）

从官方 README 确认可用的示例：

```ocaml
8::16                    // 第 8 到第 16 泛音之间的音段
tet(10)                  // 10 平均律
sort(3^[-1..5] rdc 2)    // 毕达哥拉斯律的大调音阶
```

并支持给音级附加**名称与颜色**（`9/8 white "Major 2nd"`）——这对可视化直接有用（音级着色）。导出 `.swi` interchange 格式，另有 `temper`、`warts`、`monzo`、`pythagorean`、`diamond-mos` 等子模块。

**结论**：sonic-weave 直接解决了"律制计算"这个最难又最不该自研的部分，且是 MIT。**应当采用。**

## 3. 律制家族逐类实现方案

| # | 家族 | 实现方式 | 难度 | 备注 |
|---|---|---|---|---|
| 1 | **五度相生 / 毕达哥拉斯** | 3:2 叠置，模 2 归八度 | 易 | sonic-weave 有 `pythagorean` 模块；中国三分损益法同构 |
| 2 | **纯律 (Just Intonation)** | 简单整数比集合（5-limit、7-limit…） | 易 | 需处理**音 comma 漂移**与 wolf 音程 |
| 3 | **中庸律 / 历史律制** | 音 comma 在五度上的分配 | 中 | sonic-weave 的 `temper` 模块可做；四分之一音 comma 等 |
| 4 | **十二平均律** | 12-EDO | 易 | 基准 |
| 5 | **其他等分八度** | n-EDO：7(泰/缅)、19、24、31、53 | 易 | `tet(n)` 一行即可；53-EDO 是纯律的极佳近似 |
| 6 | **微分音 / 中立音** | 24-TET 或比例 | 中 | **理论 vs 实践有差**：阿拉伯 24 律是理论框架，实际演奏的中立音是浮动、依赖地区的 |
| 7 | **非等分合奏调音** | **实测频率集合** | 难 | 需 `Pitch.absolute`；数据见 §4 |
| 8 | **五声 / 七声自然音** | 多为 12-TET 或纯律子集 | 易 | 中国宫商角徵羽、日本都节/琉球、韩国、凯尔特、安第斯 |
| 9 | **调式—旋律框架** | **框架层**，非音高层 | 难 | 拉格/木卡姆/达斯特加赫，需行为数据 |
| 10 | **口传 / 非固定音高** | ⚠️ 不做音阶化 | — | 见 §5 |

## 4. 数据源（含许可证风险）

### 4.1 音阶 / 律制库

| 来源 | 内容 | 许可风险 |
|---|---|---|
| **Huygens-Fokker Scala 归档** | 数千个 `.scl` 文件 | ⚠️ **需确认再分发条款**（归档免费下载 ≠ 可自由再分发）。建议：提供解析器 + 链接，**不打包**音阶文件 |
| **Xenharmonic Wiki** | 社区整理的音阶/律制知识 | ⚠️ Wiki 内容许可需确认（通常 CC BY-SA，**有传染性**，注意与代码分离） |
| **Sevish / Scale Workshop 音阶仓库** | 大量实用音阶 | ⚠️ 需逐个确认 |
| **Wilsonic 内置音阶** | Erv Wilson 理论导出的音阶 | ⚠️ 需确认 |

> **架构建议**：**音阶数据与代码分离**。代码用 MIT，数据放独立仓库/独立目录并保留各自许可声明，避免许可证混同。且优先"运行时按需获取 + 用户自备"，而非打包进发行版。

### 4.2 世界音乐语料（学术）

| 来源 | 内容 | 许可 |
|---|---|---|
| **CompMusic** (UPF) | 印度（Hindustani/Carnatic）、土耳其木卡姆、北京京剧等多文化音乐语料 | ⚠️ **多为研究用途许可**，禁止商用/再分发 |
| **Saraga** (CompMusic) | 印度艺术音乐标注数据集（含 raga 标注） | ⚠️ 研究用途 |
| **Dunya** (CompMusic) | 土耳其木卡姆录音与标注 | ⚠️ 研究用途 |
| **Gamelan 调音实测数据** | 散见于民族音乐学论文 | ⚠️ 零散，需逐个溯源 |

> **明确警告**：这些数据集**不可默认用于开源项目发行版**。合法用法是：引用论文中的**测量结果数值**（事实数据，通常不受版权保护）并注明出处，而非再分发音频或标注文件。

### 4.3 拉格 / 木卡姆结构数据

生成器需要的**不只是音高**：

| 体系 | 必需字段 |
|---|---|
| 印度拉格 | `aroha`（上行）、`avaroha`（下行）、`vadi`（主音）、`samvadi`（次主音）、`pakad`（特征乐句）、`thaat`（归类）、时间/情绪关联 |
| 阿拉伯木卡姆 | `ajnas`（音细胞，约三音/四音）、`seyir`（行进性格：上升/下降/混合）、惯例起音、`qarar`/`ghammaz`（停留音） |
| 波斯达斯特加赫 | `gusheh`（小段）、`forud`（回落乐句）、行进模式 |
| 土耳其木卡姆 | `seyir`、`durak`（停留音）、`guclu`（强音）、`yeden`（导音） |
| 甘美兰 | `pathet`（调式类别）、`embat`（音程宽度感）、乐器功能分层 |

**现实评估**：这些结构数据**没有权威的开源机器可读全集**。南印度有 72 个 `melakarta` 基本拉格的系统化列表（数学可枚举，✅ 可实现），但**具体的 `pakad` 与即兴规则是口传的**，只有零散学术记录。

> **建议**：先实现**可枚举的部分**（音阶集合、aroha/avaroha、melakarta 体系），框架层用少量**人工整理的样例**（每个体系 3–5 个），并明确标注"这是简化模型，非该传统的权威表达"。

## 5. 明确无法忠实实现的部分

| 传统 | 为什么做不到 | 替代产品形态 |
|---|---|---|
| **蒙古呼麦 / 泛音唱法** | 本质是**人声的泛音选择**，音高由口腔共振峰决定，非固定音阶 | 提供**泛音列交互工具**（显示基音的泛音序列，用户可"选择"强调哪个泛音），而非"生成呼麦" |
| **因纽特喉音 (katajjaq)** | 节奏性呼吸游戏，音高次要 | 节奏交互游戏，不做音高建模 |
| **原住民 / 口传传统** | 无固定音高、强调滑音与腔化；且**部分传统有文化使用禁忌** | ⚠️ **建议整体不做**。文化挪用风险高于技术收益 |
| **甘美兰合奏** | 每套调音不同、乐器有配对调音（`pengumbang`/`pengisep` 微差产生拍频） | 用**实测频率集**做近似；明确标注"基于某套特定合奏的测量" |

> **伦理红线**：对活态口传传统，"生成一段 XX 音乐"这种产品形态本身就是问题。建议的方向是**工具而非模仿**——给用户能探索该体系**原理**的交互界面。

## 6. 实施建议

### 6.1 数据模型

```ts
interface TuningSystem {
  id: string;
  name: string;
  family: TuningFamily;          // 10 类家族枚举
  kind: 'edo' | 'ratio-set' | 'measured' | 'formula';
  // edo:       { divisions: n }
  // ratio-set: { ratios: [number, number][] }
  // measured:  { frequenciesHz: number[], refHz: number }
  // formula:   { expr: string }   // sonic-weave 表达式
  periodCents: number;           // 通常 1200（八度），但甘美兰等可能不同
}

interface Scale {
  tuningId: string;
  degrees: number[];             // 取律制中的哪些步进
}

interface Framework {              // 框架层
  scaleId: string;
  ascending?: number[];          // aroha
  descending?: number[];         // avaroha
  emphasis?: Record<number, number>;  // 音级 → 权重（vadi/samvadi/durak）
  phrases?: Phrase[];            // pakad / 惯用乐句
  direction?: 'ascending' | 'descending' | 'mixed';
  notes?: string;                // 人类可读说明与出处
}
```

### 6.2 分期

- **M2（律制层）**：sonic-weave 接入 + `.scl` 解析 + 家族 1–5、8（易实现的精确体系）+ 音分偏差可视化
- **M3（框架层）**：框架数据模型 + 家族 6、9 的少量样例 + 家族 7 的实测频率支持
- **不做**：家族 10

### 6.3 始终显示的诚实标注

界面上对每个体系给出：
- 该实现的**依据来源**（论文/标准/社区）
- **偏离程度**（如"本实现为简化模型，未包含 X 与 Y"）
- 对该传统的**指路**（推荐去听真实的录音）

这既是学术诚信，也是产品差异化——**大多数音乐软件从不做这件事**。
