# 07 · 体验优先：怎么让人点几下就好听，还觉得好玩

> 本文是**重心的纠正与产品设计原则**。
> 起因：前几份文档把"拉格/木卡姆/甘美兰"当成了目标，但它们只是用户举例说明**"兼容面要广"**。
> 用户真正要的是：**简单点击调参、或以轻松游戏的方式，就能创造出有趣的、动听的音乐。**

---

## 0. 重新排序的优先级

之前的隐含优先级（错）：

```
律制覆盖广度 > 生成引擎 > 听感 > 交互
```

纠正后的优先级（对）：

```
① 听感（好听到能听下去）        ← 命门。不好听，其他全部白费
② 交互（零门槛、有即时反馈）     ← 决定用户是否留在第一分钟
③ 玩法（轻松的游戏形式）         ← 决定用户是否回来
④ 生成算法的丰富度              ← 决定长期可玩性
⑤ 体系兼容广度（律制/音阶/框架）  ← 架构的容错性，不是卖点
```

**关键转变**：
- ⑤ 从"核心差异化承诺"降级为"**架构上留好口子，但不作为产品主张**"
- ① 从"次要"升级为"**工程上必须专门攻坚的问题**"

> ⑤ 是"能力"，不是"卖点"。用户不需要知道背后支持多少种律制；他们只需要觉得**好听、好玩、能一直玩下去**。

---

## 1. 命门：让随机生成的东西"好听"

这是本项目**最大的技术风险**，而且它和"支持多种律制"完全无关。
demo 的五声音阶量化只是最低限度——它能去掉"错音"，但离"动听"还很远。

### 1.1 为什么随机选取参数往往难听

如果每个参数都在自己的合法范围内独立随机（demo 就是这样：随机声部 × 随机音高 × 随机间隔），结果会：

- **音区混乱**：各声部音高互相打架，低频堆积、高频刺耳
- **和声冲突**：随机音高同时响起，出现小二度/三全音这类紧张音程
- **密度失控**：瞬间十几个音一起响（demo 用限流打补丁，但只是缓解）
- **无方向感**：没有起承转合，听 20 秒就腻
- **音量失衡**：不同音区等音量 → 低频轰、高频尖

### 1.2 解法一（最重要）：**在"好听的子空间"里随机**

**核心原则：随机性只能在已知悦耳的范围内采样。**

不是"生成声音然后检查是否好听"，而是**从一开始就不进入难听区域**。具体做法：

| 手段 | 作用 |
|---|---|
| **音阶/调式约束** | 最基础的一层（demo 已有）。但要选**悦耳音阶**，而非任意音阶 |
| **和声约束** | 同时发声的音必须落在许可的和声集合内（三和弦/七和弦/挂留） |
| **声部音区隔离** | 每个声部有严格音域，且互不重叠（低音<和声<旋律<打击） |
| **音程优先权重** | 生成下一音时，按音程"悦耳度"加权（纯五/三度权重高，小二度近乎为0） |
| **密度包络** | 密度随时间平滑变化，禁止瞬间突变 |
| **避免同度/八度碰撞** | 防止声部合并导致的相位与音量问题 |
| **音色分层** | 低频用正弦/三角（厚），中频用拨弦/电钢（清），高频用噪声打击（脆） |

> **实现形态**：把它做成**"悦耳度评分 + 加权采样"**。生成候选音 → 打分 → 按分加权选一个。
> 这比"硬约束"更宽容（不会卡死），又比纯随机好听得多。

### 1.3 解法二：**预设质量下限**

**每个内置预设都必须经过人工试听确认"好听"。** 这是最朴素也最有效的手段。

- 预设不是"一套参数"，而是"**一个被验证过好听的作品种子库**"
- 用户点"生成"，实际是在**已验证好听的区域附近做小扰动**，而不是全空间随机
- 这让"随便点"也能有质量保证

> 这条比任何算法都重要：**如果 20 个预设里有 3 个难听，用户就会觉得"这软件不行"**。
> 建议把"每个预设连续试听 2 分钟不出难听片段"作为发布门槛。

### 1.4 解法三：**宏观结构提供方向感**

随机音符 + 无结构 = 很快腻。需要有：

- **段落**：进入 → 铺展 → 变化 → 回落（哪怕只有 4 个段落）
- **密度曲线**：缓慢起伏，不是均匀喷洒
- **音色进退**：声部逐层加入/退出（比"一直四个声部全响"耐听得多）
- **偶尔的"事件"**：一个高音、一次停顿、一个转调暗示——制造记忆点

### 1.5 解法四：**混音是听感的一半**

很多生成音乐难听，不是旋律问题，是混音问题：

| 问题 | 手段 |
|---|---|
| 总线爆音 | 压缩器（demo 已有）+ 限制器 |
| 低频浑浊 | 每声部高通滤波，去掉无用的低频 |
| 高频刺耳 | 轻度齿音控制/高频滚降 |
| 声音干瘪 | 卷积混响（程序生成的 IR 即可） |
| 声部打架 | 声部均衡分频（各占一段频段）+ 音量平衡 |
| 立体声过窄 | 声部轻微左右分布 |

> **建议**：把混音链做成**固定的、经过调校的默认值**，用户不需要懂，但一定要有。

### 1.6 验证方法（可执行）

不要靠感觉，要能测：

- **自动化检查**：生成 1000 个种子，统计"难听事件"（不协和音程数、密度超限次数、音区冲突次数）→ 应低于阈值
- **人工盲测**：随机抽 20 个片段让人打分，均分低于阈值就回炉
- **长时试听**：连续播放 10 分钟，检查是否出现"想关掉"的时刻

## 2. 交互：难度阶梯（不是三个界面，是同一条斜坡）

用户要的是"简单点击调整不同参数，或者以轻松的游戏形式"。
**不要用"简单模式/专业模式"这种二分**——那是一堵墙。要的是一条**平滑的斜坡**：

```
第 0 级 · 零操作       按一下"播放"，就出好听的音乐
                       （预设曲目；用户什么都不用懂）
        ↓
第 1 级 · 三颗旋钮     情绪（明亮↔幽暗）｜能量（安静↔热闹）｜速度
                       ★ 这三个词非音乐人也能懂，且立刻听到变化
        ↓
第 2 级 · 换一换       整组参数的随机重掷（保留/锁定喜欢的部分）
                       "锁定节奏，换一个旋律" —— 这是最符合直觉的操作
        ↓
第 3 级 · 图层开关     逐声部开/关（demo 的 mixer 就是这个，保留并强化）
        ↓
第 4 级 · 参数显形     展开后看到真正的参数名（音阶、密度、衰减…）
        ↓
第 5 级 · 深度探索     律制、框架、算子管道、DSP —— 给专业用户
```

**设计要点**：

| 要点 | 说明 |
|---|---|
| **第 1 级的三个词最关键** | "情绪/能量/速度"是**音乐化的抽象**，而非音乐术语。它们是"参数面上的低维投影"——背后映射到音阶亮度、密度、和声紧张度、音色等多个维度 |
| **锁定与重掷** | 用户能"保留喜欢的、重掷不喜欢的"。这是**零门槛下最强的创造感来源**（远胜于让人调参数） |
| **每一步都能立刻听到** | 任何操作必须有 **<100ms** 的听觉反馈；长时程变化要先给预览 |
| **不需要保存就能分享** | 分享码随时可复制 |
| **绝不出现"错误"** | 用户不可能"弹错"，因为一切都是量化的、悦耳的 |

> **"锁 + 重掷"是本项目最该做好的交互**。
> 它把"创造音乐"从"懂乐理"变成了"选择你喜欢的样子"——完全不需要任何音乐知识。

### 2.1 参数应当是"音乐化的抽象"，不是 DSP 术语

| ❌ 不要这样 | ✅ 要这样 |
|---|---|
| `filter cutoff: 3200Hz` | `明亮度` |
| `note density: 0.4` | `热闹程度` |
| `reverb mix: 0.3` | `空间感` |
| `detune: 7 cents` | `厚度 / 温暖感` |
| `swing: 0.12` | `摇摆感` |
| `scale: Bhairav thaat` | 预设卡片：「东方·幽暗」 |

高级模式里当然要暴露真实参数——但**默认路径上只出现人话**。

## 3. 玩法：游戏是"零门槛 + 有反馈"的合体

用户明确提到"以轻松的游戏形式"。游戏在这里的作用不是娱乐，而是**降低门槛 + 提供即时反馈**：

| 游戏形态 | 玩家的实际动作 | 音乐上的意义 | 门槛 |
|---|---|---|---|
| **节奏点击** | 跟着拍子点 | 打击声部 + 判定 | ★ |
| **音阶小径** | 在多个门中选一个前进 | 选音级，走出旋律 | ★ |
| **色彩配对** | 拖颜色到形状上 | 颜色=音高，形状=节奏 | ★ |
| **和声接龙** | 接上一块"和声积木" | 和弦进行 | ★★ |
| **氛围涂鸦** | 在画布上画 | 轨迹 → 音符/纹理 | ★ |
| **调音侦探** | 猜哪个音更高/更低 | 听辨律制差异（**顺带教学**） | ★★ |
| **合作接力** | 轮流加一层 | 逐层叠加作品 | ★ |

**设计原则**：

1. **玩本身就在生成音乐**——不是"游戏 + 音乐"，而是"游戏即作曲"
2. **不可能输**——没有失败状态，只有"不同的结果"
3. **产出可带走**——每局结束都能导出/分享这段音乐
4. **失败也是音乐**——判定错了就变成另一种音色/音级，而不是中断

> 第 3 条最重要：**让游戏的产出成为用户的"作品"**。这同时解决了"留存"和"贡献内容"两个问题——用户自然会想分享自己玩出来的东西。

### 4.1 修订后的路线图重心

```
新 M1 · 好听（听感攻坚）        ← 从"顺带"提升为独立里程碑
  · 悦耳度评分 + 加权采样的生成器
  · 混音链（压缩/均衡/混响）
  · 20 个经人工确认好听的预设
  · 自动化听感检查 + 人工盲测

新 M2 · 好玩（三旋钮 + 锁与重掷）← 零门槛交互
  · 情绪/能量/速度 三旋钮
  · 锁定与重掷
  · <100ms 反馈

新 M3 · 第一个游戏（节奏点击）    ← 验证多形态架构 + 提供"玩"的入口

新 M4 · 律制/框架（高级模式）     ← 原 M2/M3 降级后移，作为深水区
```

> **关键判断**：**"好听"必须成为独立的、排在最前面的里程碑**，而不是像原计划那样散落在各处。
> 因为它不是"某个功能"，而是**所有功能的前提**。

---

## 5. 一句话总结

> **用户不关心你支持多少种律制。他们只会记住两件事：点一下好不好听，玩一下有没有意思。**
>
> 律制/音阶/框架的广度是**架构的容错性**（保证未来能扩容、能不被西方中心主义绑死），
> 而听感与交互才是**产品的命门**。两者地位完全不同，不能混为一谈。
